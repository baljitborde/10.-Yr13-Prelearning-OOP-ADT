ADTs as Classes
● ~10 minutes

You already know the OOP terminology and you have met stacks, queues, linked lists and binary trees. This pre-learning puts the two together. In Paper 4 you may be asked to write an abstract data type (ADT) as a class in Python. The good news is that every ADT class follows the same pattern, so once you can see the pattern, the code becomes much easier.

Data → private attributes

The array that holds the items and every pointer (TopPointer, Head, Tail, Free, Root…) become private attributes, set up in the constructor.

Operations → public methods

Push, Pop, Enqueue, Dequeue, Insert, Search and Traverse become public methods. Code outside the class can only use the ADT through them. This is encapsulation.

ADTRulePrivate attributesMain methods
StackLIFO — last in, first outItems, TopPointerPush, Pop, IsEmpty, IsFull
QueueFIFO — first in, first outItems, Head, Tail, NumberOfItemsEnqueue, Dequeue
Linked listEach node points to the next nodeNodes (Node objects), Head, FreeAddToFront, Traverse, Search
Binary treeLeft is smaller, right is larger or equalNodes (TreeNode objects), Root, NextFreeInsert, Search, InOrder
Two kinds of class: stacks and queues need only one class. Linked lists and binary trees need two: a small Node class for one item and its pointer(s), and a main class that contains an array of Node objects. That is containment.
The null pointer: on this page, -1 means "points to nothing" (an empty stack, the end of a list, no child). It cannot be 0, because 0 is a real array index.
✎ Worked exam-style question
Explain why the pointers in a Stack class are declared as private attributes. [2]
Think of your answer first, then reveal the mark scheme.
Mark scheme — one mark for each point:
  • So they cannot be changed directly by code outside the class
  • They can only be changed through the methods Push() and Pop(), which check for full / empty, so the stack cannot be corrupted (e.g. TopPointer pointing outside the array)
Examiner tip: Name the actual methods from the question. This is what turns a general point about encapsulation into an answer about this ADT.

Stack
● ~15 minutes
Quick recap: A stack is LIFO. A single pointer, TopPointer, holds the index of the item at the top. It starts at -1 (empty). Push moves the pointer up, then stores; Pop reads the top item, then moves the pointer down.
Python — the Stack class
class Stack: def __init__(self, Size): self.__Items = [""] * Size self.__Size = Size self.__TopPointer = -1 # empty def IsEmpty(self): return self.__TopPointer == -1 def IsFull(self): return self.__TopPointer == self.__Size - 1 def Push(self, NewItem): if self.IsFull(): return False self.__TopPointer = self.__TopPointer + 1 self.__Items[self.__TopPointer] = NewItem return True def Pop(self): if self.IsEmpty(): return None Item = self.__Items[self.__TopPointer] self.__TopPointer = self.__TopPointer - 1 return Item
Stack
- Items : ARRAY
- Size : INTEGER
- TopPointer : INTEGER
+ Constructor(Size)
+ IsEmpty() : BOOLEAN
+ IsFull() : BOOLEAN
+ Push(NewItem) : BOOLEAN
+ Pop() : STRING
Main program
Plates = Stack(5) Plates.Push("Red") Plates.Push("Blue") print(Plates.Pop()) # Blue print(Plates.Pop()) # Red print(Plates.Pop()) # None
Order matters: in Push, add 1 to TopPointer before storing the item. In Pop, read the item before taking 1 off TopPointer. Swapping these lines is the most common stack bug.
✎ Worked exam-style question
Write the method Pop() for the Stack class. It returns the item at the top of the stack, or None if the stack is empty. [4]
Think of your answer first, then reveal the mark scheme.
Mark scheme — one mark for each point:
  • Method header def Pop(self):
  • Checks whether the stack is empty (TopPointer == -1 / IsEmpty()) and returns None
  • Reads the item at self.__Items[self.__TopPointer]
  • Decreases TopPointer by 1 and returns the item
Examiner tip: Each mark is for one step. Even if you cannot remember all of it, the header and the empty check are easy marks.

Queue
● ~15 minutes
Quick recap: A queue is FIFO. Items join at the tail and leave from the head. In a circular queue the pointers wrap round to 0 when they pass the end of the array, so freed spaces at the front are reused. NumberOfItems tells you if it is empty (0) or full (equal to Size).
Python — a circular Queue class
class Queue: def __init__(self, Size): self.__Items = [""] * Size self.__Size = Size self.__Head = 0 self.__Tail = -1 self.__NumberOfItems = 0 def Enqueue(self, NewItem): if self.__NumberOfItems == self.__Size: return False # full self.__Tail = (self.__Tail + 1) % self.__Size self.__Items[self.__Tail] = NewItem self.__NumberOfItems = self.__NumberOfItems + 1 return True def Dequeue(self): if self.__NumberOfItems == 0: return None # empty Item = self.__Items[self.__Head] self.__Head = (self.__Head + 1) % self.__Size self.__NumberOfItems = self.__NumberOfItems - 1 return Item
How the wrap-around works

In a queue of size 5, the indexes are 0 to 4. When Tail is 4:

(4 + 1) % 5 = 5 % 5 = 0

So the next item goes back to index 0. The % (MOD) operator does the wrapping for both pointers.

Main program
Printer = Queue(3) Printer.Enqueue("Job1") Printer.Enqueue("Job2") print(Printer.Dequeue()) # Job1
Why start Tail at -1? Enqueue moves Tail before storing, so the first item goes to index (-1 + 1) % Size = 0, the same index as Head.
✎ Worked exam-style question

Mark scheme — one mark for each point:

  • Moves Tail on by one, wrapping to 0 using (Tail + 1) % Size
  • Stores the item at the Tail position and adds 1 to NumberOfItems

Linked List
● ~20 minutes
Quick recap: A linked list stores each item in a node with a pointer to the next node. In OOP, a Node class holds one item and its NextNode pointer. The LinkedList class contains an array of Node objects, a Head pointer to the first node in the list, and a Free pointer to the first unused node.
Python — the Node class
class Node: def __init__(self, Data, NextNode): self.__Data = Data self.__NextNode = NextNode def GetData(self): return self.__Data def GetNext(self): return self.__NextNode def SetData(self, NewData): self.__Data = NewData def SetNext(self, NewNext): self.__NextNode = NewNext
A new LinkedList(4)
IndexDataNextNode
0""1
1""2
2""3
3""-1
Head = -1Free = 0

All four nodes start in the free list, linked 0 → 1 → 2 → 3. The list itself is empty.

Python — the LinkedList class
class LinkedList: def __init__(self, Size): self.__Nodes = [] for Index in range(Size): self.__Nodes.append(Node("", Index + 1)) self.__Nodes[Size - 1].SetNext(-1) self.__Head = -1 # list is empty self.__Free = 0 # first free node def AddToFront(self, NewData): if self.__Free == -1: return False # no free nodes NewIndex = self.__Free self.__Free = self.__Nodes[NewIndex].GetNext() self.__Nodes[NewIndex].SetData(NewData) self.__Nodes[NewIndex].SetNext(self.__Head) self.__Head = NewIndex return True def Traverse(self): Current = self.__Head while Current != -1: print(self.__Nodes[Current].GetData()) Current = self.__Nodes[Current].GetNext()
Objects talk through methods: LinkedList cannot read a node's private __NextNode, so it uses GetNext() and SetNext(). Containment and encapsulation together.
✎ Worked exam-style question
Explain why the LinkedList class needs a Free pointer as well as a Head pointer. [2]
Think of your answer first, then reveal the mark scheme.
Mark scheme — one mark for each point:
  • Head points to the first node that is in use / the start of the list
  • Free points to the first unused node, so AddToFront() knows where to store new data without searching the array
Examiner tip: Two pointers, two marks: say what each one points to.

Binary Tree
● ~20 minutes
Quick recap: In a binary search tree each node has a left and a right pointer. Values smaller than a node go to its left; values larger (or equal) go to its right. A TreeNode class holds the data and both pointers; the BinaryTree class contains an array of TreeNode objects plus a Root pointer.
Python — the TreeNode class
class TreeNode: def __init__(self, Data): self.__Data = Data self.__Left = -1 self.__Right = -1 def GetData(self): return self.__Data def GetLeft(self): return self.__Left def GetRight(self): return self.__Right def SetLeft(self, NewLeft): self.__Left = NewLeft def SetRight(self, NewRight): self.__Right = NewRight

Python — the BinaryTree class
class BinaryTree: def __init__(self, Size): self.__Nodes = [None] * Size self.__Root = -1 self.__NextFree = 0 def GetRoot(self): return self.__Root def Insert(self, NewData): if self.__NextFree == len(self.__Nodes): return False # tree is full NewIndex = self.__NextFree self.__Nodes[NewIndex] = TreeNode(NewData) self.__NextFree = self.__NextFree + 1 if self.__Root == -1: self.__Root = NewIndex # first node return True Current = self.__Root Placed = False while not Placed: if NewData < self.__Nodes[Current].GetData(): if self.__Nodes[Current].GetLeft() == -1: self.__Nodes[Current].SetLeft(NewIndex) Placed = True else: Current = self.__Nodes[Current].GetLeft() else: if self.__Nodes[Current].GetRight() == -1: self.__Nodes[Current].SetRight(NewIndex) Placed = True else: Current = self.__Nodes[Current].GetRight() return True def InOrder(self, Index): if Index != -1: self.InOrder(self.__Nodes[Index].GetLeft()) print(self.__Nodes[Index].GetData()) self.InOrder(self.__Nodes[Index].GetRight())
Recursion for traversal: InOrder() calls itself on the left subtree, outputs the node, then calls itself on the right subtree. The base case is Index == -1 (no node), where it does nothing. In-order traversal of a binary search tree outputs the values in ascending order. Call it from the main program with Tree.InOrder(Tree.GetRoot()).
✎ Worked exam-style question
Describe how the Insert() method finds the correct position for a new value. [3]
Think of your answer first, then reveal the mark scheme.
Mark scheme — one mark for each point:
  • Starts at the Root node (Current = Root)
  • Compares the new value with the current node: if smaller, follows the Left pointer; otherwise follows the Right pointer
  • Repeats until the pointer it needs is -1, then sets that pointer to the new node's index
Examiner tip: Use the words "left", "right", "root" and "-1" in your answer. They are what the mark scheme looks for.

Exam Practice: Choosing & Debugging ADTs
● ~10 minutes

Exam questions on ADTs usually ask you to choose the right ADT for a scenario, trace the pointers, or write one method. Use this checklist every time you write an ADT method.

CheckWhy it matters
Is self the first parameter?Without it, Python raises a TypeError when the method is called.
Is every attribute written self.__Name?Without self. you create a local variable that is lost.
Have you checked for full or empty first?Easy marks, and it stops the pointers going outside the array.
Are the pointer steps in the right order?Push: move then store. Pop: read then move. AddToFront: update Free before overwriting the pointer.
Do you use getters and setters on Node objects?A node's attributes are private to the Node class.
Does the method return what it should?Pop and Dequeue return the item; Push and Enqueue return True or False.
Exam technique: trace with a table. Write down every pointer (TopPointer, Head, Tail, Free, Root) and update it line by line. Most tracing errors come from doing it in your head.

✓ Summary — CIE 9618 Topic 20.1: Coding ADTs with OOP
ADT as a class: the array and pointers are private attributes set up in the constructor; the operations are public methods. -1 is the null pointer.
Stack (LIFO): one pointer, TopPointer, starting at -1. Push: check full, move up, store. Pop: check empty, read, move down.
Queue (FIFO): Head, Tail and NumberOfItems. Enqueue moves Tail; Dequeue moves Head; both wrap with % Size.
Linked list: a Node class (Data, NextNode) plus a LinkedList class containing an array of nodes, a Head pointer and a Free pointer. Traverse by following GetNext() until -1.
Binary tree: a TreeNode class (Data, Left, Right) plus a BinaryTree class with a Root pointer. Smaller values go left. In-order traversal is recursive and outputs ascending order.
OOP techniques used: encapsulation (private data, public methods), getters and setters on nodes, and containment (a list or tree has nodes).
